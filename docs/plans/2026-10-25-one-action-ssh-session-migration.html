Move an Untether session with one action

Set up your VPS address, selected SSH identity, trusted host key and project mapping once. Then select a session in Telegram and choose Move → VPS, or run one command. For the return trip, initiate a pull from the local bot if the VPS cannot reach your local machine.

Not implemented or deployed. This is the companion to the detailed Markdown plan/spec. It does not authorise SSH access, installation or restarting your running bot.

What I found in the actual Coddy repository

coddy-project/coddy-agent, pinned commit da8fdeb is the correct repository. Its remote mode makes a client talk to sessions already stored on the VPS. It does not transport a local session there. Its session bundle contains more than conversation text; its export is not a lossless restore archive. Its SSH host-key auto-replacement should not be reused; changing keys must halt the transfer. See the source evidence.

One-time setup, not every transfer

VPS

Host, port, account, installed Untether path and destination project map.

SSH identity

Select a particular key inside your key folder. The private key never travels. Use SSH-agent for passphrase unlock.

Trust

Verify and pin the VPS host-key fingerprint out of band. Reject any changed key; do not auto-accept.

Telegram

Use your allowed user ID on both bots, but separate bot tokens. Telegram identity is access control, not session synchronisation.

Examples after setup: /session move <id> --to vps --project projects or /session move <id> --from vps --project projects. The Telegram button calls the same operation. Status and recovery errors remain visible in chat.

What “move” really preserves

ModeWhat arrivesWhen advertised

Project filesSeparate Git sync or explicitly approved bounded file bundleNever implied by session transfer

In-flight tools, hidden reasoning, credentials, permission grants and unsynced project files are not restored. If the target cannot actually resume, Untether must say so and leave the source usable.

Works with any Linux VPS — Coolify is optional

Mandatory: support native Linux installations and container deployments, with or without Coolify, using the same SSH receiver protocol. No dependency on a particular distribution, systemd, root access, Docker, fixed paths or public API. Native profiles specify executable and state/project roots; container profiles additionally specify a restricted wrapper and verified mount/UID mapping. Test native Linux, ordinary containers and Coolify containers in both directions. An offline or unconfigured VPS fails preflight with an actionable explanation; never install prerequisites silently.

Availability fuses — checked on every transfer

The receiver must be reachable and trusted, not merely configured. Preflight checks SSH authentication, protocol compatibility, installed command metadata, actual container readiness, agent executable/version/capabilities, provider authentication and network, destination project/Git parity, free disk/inodes, private staging permissions, no active tools, and destination Telegram authorisation. Every phase has a timeout and bounded retries; trust/auth/schema failures stop immediately.

Actual VPS deployment: the newest Woody runbook describes Coolify-managed Untether + Pi containers, not a host Python service. A fixed least-privilege receiver wrapper and mount/UID mapping must be verified; do not assume a host-level Untether executable exists. Pi installed does not prove ACP availability. No live VPS check was performed.

Independent Gemini/Argon review

Review thread: accepted bot handoff, workspace parity, schema handshake, bounded quiescence and lost-receipt recovery. Different bots cannot seamlessly transfer a private Telegram chat: enrol the destination bot/chat and return its link. Reject blind rewriting of transcript paths/line endings and Git storage of sensitive session state. Preserve historical bytes and map only structured paths.

Complete proposed settings template includes phase timeouts, size/disk limits, retries, SSH identity and receiver binding. Actual endpoint inventory stays local outside Git. These settings are not active until typed schema support exists; the live bot config is unchanged.

Implementation phases

  1. Inventory: verify installed command metadata, runner state formats, and actual SSH reachability. Start with the existing ACP archive; no invented universal native archive.
  2. Profiles: validate VPS, selected key, pinned host and explicit project map. Preflight installed Untether and target agent.
  3. Transfer: freeze selected session, snapshot, hash and upload to a private staging directory through SSH; receiver validates before any state change.
  4. Resume and ownership: import, restart/load probe, durable receipt, idempotent retry and fencing. Switch only the selected chat/topic when verified.
  5. Interface: one CLI operation shared by Telegram Move/Copy button and status command, including local-initiated reverse pull.
  6. Native adapters: add per-provider only after proving real native resume on disjoint stores. Test both directions on disposable hosts before rollout.
